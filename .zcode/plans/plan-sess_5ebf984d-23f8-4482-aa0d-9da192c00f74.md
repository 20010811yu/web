# 制定项目 Rules + Memory Bank + Skill 计划（融合 memory-bank.md，Element Plus 版）

## 目标
在 D:\website 建立：① 融合记忆库体系的项目规则 AGENTS.md；② 初始化 memory-bank/ 目录；③ 3 个与 P0–P5 生命周期挂接的自定义 skill。全部随仓库版本化。技术栈确认为 Vue 3 + Vite + Element Plus（按需引入 + 自定义主题色）。

## 一、项目规则：`D:\website\AGENTS.md`

以 memory-bank.md v2.1 为骨架做 ZCode 适配（去掉 attempt_completion 等 Cline 专属术语），叠加官网项目规范：

**第一部分：记忆库工作流（源自 memory-bank.md，硬约束）**
- 三条铁律：先读后动 / 写必有因 / 交付必同步
- P0–P5 六阶段任务生命周期与文件读写时机矩阵（7 个核心文件固定顺序全量必读）
- 写入触发条件与禁写边界
- 体积红线与归档机制（activeContext ≤150 行、progress ≤80 行、systemPatterns ≤210 行；errorlog 🟢 条目压缩；memory-bank/archive/ 归档，P0 不读）
- P4 任务后同步检查（逐文件检查清单、变更→文件映射表、一致性红线）
- P5 Git 同步：完成后必须 add -A → commit → push，Conventional Commits，push 失败处理

**第二部分：官网项目规范**
- 技术栈：Vue 3 `<script setup>` + Vite + Vue Router + vue-i18n + **Element Plus**
  - 按需引入：unplugin-vue-components + ElementPlusResolver，组件与样式自动按需加载，禁止全量 `app.use(ElementPlus)`
  - 自定义主题：通过 CSS 变量覆盖（`--el-color-primary` 等）统一品牌色；项目自有样式写在 design tokens 变量体系中
  - Message/MessageBox 等函数式组件单独引入并配置样式按需
- 目录结构与职责（views/components/data/i18n/assets/styles）
- 双语规范：文案必须中英同步进语言包，禁止硬编码；Element Plus 内置文案 locale 跟随 vue-i18n 语言切换（zh-cn / en）
- 数据规范：占位数据统一放 src/data/
- 命名/样式规范：组件 PascalCase、Element Plus 组件在模板中用 kebab-case 或统一风格、CSS 变量优先、响应式断点
- 提交前必须 npm run build 通过（纳入 P4 检查）

## 二、初始化记忆库：`D:\website\memory-bank\`

按 §2.1 创建 7 个核心文件骨架：projectbrief.md（填入官网项目概述与技术栈）、productContext.md、activeContext.md、systemPatterns.md、techContext.md（填 Vue3+Vite+Element Plus 及按需引入/主题约束）、progress.md、errorlog.md，并创建 archive/ 目录。

## 三、3 个自定义 skill：`D:\website\.zcode\skills\`

1. **company-website-dev/**（官网开发流程）：P0 全量必读记忆库 → P1 澄清+规划+写 activeContext → P2 按 AGENTS.md 规范实施（Element Plus 按需使用、双语同步）+错误实时入档 → P3 验证 → 汇报
2. **add-page/**（新增页面）：前置 P0 必读 → 固定步骤（视图/路由/导航/i18n 双语/Element Plus 组件选用与主题变量/响应式）→ P4 同步检查清单 → 构建验证
3. **pre-commit-check/**（提交前检查 = P4+P5）：npm run build 通过 → 硬编码文案扫描 → 逐文件同步检查记忆库 + 体积红线核对 → 输出检查清单 → Conventional Commits 提交并 push → 附提交哈希
