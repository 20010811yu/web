# 部署（GitHub Pages）+ CMS 后台（Decap）实施计划

## 一、部署：GitHub Actions 自动发布到 GitHub Pages
1. `vite.config.js`：设 `base: '/web/'`（仓库名 web，GitHub Pages 项目页路径）
2. 新增 `.github/workflows/deploy.yml`：push main → npm ci/build → 复制 `dist/index.html` 为 `dist/404.html`（SPA 路由回退）→ 部署到 Pages
3. 我会用 `gh` CLI 尝试直接启用仓库 Pages（build_type=workflow）；若 CLI 未授权则给你一步手动开关指引（Settings → Pages → Source 选 GitHub Actions）

## 二、CMS 后台（Decap CMS，/admin 路径）
**内容重构**（Decap 只能编辑 JSON/YAML/MD，把高频更新内容抽成 JSON）：
4. 新建 `src/data/content/news.json`：新闻条目（id/date/title/summary/body，中英字段并列）
5. 新建 `src/data/content/jobs.json`：职位列表
6. 新建 `src/data/content/site.json`：联系方式/地址/ICP/公司名等站点信息
7. 重构引用：News/NewsDetail/Home 读 news.json；Careers 读 jobs.json；FooterBar/Contact 读 site.json（i18n 语言包保留界面级文案；新闻职位站点信息改由 CMS 数据驱动，渲染助手 tv() 按语言取值）

**CMS 本体**：
8. `public/admin/index.html`：加载 Decap CMS CDN
9. `public/admin/config.yml`：backend github + PKCE 登录、media_folder `public/images/uploads`、三个集合（新闻/职位/站点设置，字段含中文、英文两列）
10. 登录配置：需你在 GitHub 创建一个 OAuth App 拿 Client ID（我会给逐步指引，含 localhost 和正式域名两个回调地址的填法），填入 config.yml 的 app_id 后后台即可登录
